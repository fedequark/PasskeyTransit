# Open Android CXF passkey extension audit

Checked 2026-10-26. This is a **source comparison and verification of the providers' own CI test reports**, not an Android transfer or an independent execution of their test suites. The retained [report](../experiments/android_cxf_open/report.json) pins [Keyguard `ef84e29`](https://github.com/AChep/keyguard-app/tree/ef84e290665277866adcb7f061824de06f43ef9c) and [Monica `5ef2f3a`](https://github.com/Monica-Pass/Monica/tree/5ef2f3a64b53094351210f1e316fbab51852708e). Run `python tools/verify_android_cxf_open.py` for the retained XML; replay the source inspection with `python tools/audit_android_cxf_open.py --keyguard <pinned-keyguard-checkout> --monica <pinned-monica-checkout> --output <report.json>`.

The three selected XML files are retained in `experiments/android_cxf_open/upstream/`. Their original GitHub artifact digests and the seven inspected source hashes are recorded in the report. The local audit and clean PasskeyTransit CI replay check the exact pinned source paths and compare the resulting JSON byte for byte.

**Implication for the next experiment:** a basic passkey may be accepted on paths that cannot preserve PRF state. A PRF-bearing synthetic passkey must be measured separately, with both the import disposition and RP PRF output recorded. No Keyguard-to-Monica transfer has been run here. The Android provider-events path carries CXF JSON; this result makes no claim about the draft CXP ZIP/JWE profile.
