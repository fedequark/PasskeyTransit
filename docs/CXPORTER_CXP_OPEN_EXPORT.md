# Open CXP ZIP/JWE exporter control

The selected open implementation is [`nvinuesa/cxporter`](https://github.com/nvinuesa/cxporter), pinned at commit `96bab31fdadcfd295542bba86b8ec8bd2355294a`. Its `internal/cxp` package creates an encrypted ZIP export. Our small Go adapter loads a synthetic CXF passkey document and calls that package's `ExportResponse`. The adapter is copied into the pinned source checkout at replay time to satisfy Go's `internal` import rule. We do not modify the exporter package.

The project Python importer opens the returned ZIP, checks the index and document member names, decrypts both JWEs using a fresh recipient X25519 key, and compares the recovered passkey identity, signing key, user handle and HMAC extension state against the synthetic source. It rejects a wrong recipient and independently changed ciphertext in each member. The recovered CXF is passed to the pinned Proton Pass common 2.0.0 software authenticator; a public verifier recomputes eight ES256 signatures and eight PRF digest bindings over two repetitions and two salts. The local report is [`experiments/cxporter_cxp_open/report.json`](../experiments/cxporter_cxp_open/report.json). The clean Ubuntu run is [GitHub Actions 40350620050](https://github.com/fedequark/PasskeyTransit/actions/runs/40350620050); its original artifact ZIP has SHA-256 `e880f5a48b530caff22e7149e6b436d2a1c0451de5ca0d86a0e7c1898454cd09`.

The scoped control passed, but the exporter response **omits the required `archive` member** shown in the [FIDO CXP Working Draft response schema](https://fidoalliance.org/specs/cx/cxp-v1.0-wd-20241003.html). Its JWE uses `HPKE-Base-X25519-SHA256-AES256GCM`, distinct from the `HPKE-3-KE` JOSE profile in our separate `jwx/v4` control. The Python importer handles this specific format; compatibility with other CXP implementations is not established. `cxporter` is a CLI converter, not an installed passkey provider or a persistent destination vault. The CXF source document and Python importer are project-authored. Neither two-provider CXP interoperability nor an Android provider migration is evidenced here.

Run the public evidence check with `python tools/verify_cxporter_cxp_public_report.py --report experiments/cxporter_cxp_open/report.json`. The verifier checks retained public signatures and synthetic PRF relations; archive and decryption claims require replaying `.github/workflows/cxporter-cxp-open.yml`. The local and CI reports contain public transcripts and digests, not private keys, HMAC seeds, raw PRF values or ciphertext. Two repetitions characterize this selected code path; they are not a reliability estimate.
