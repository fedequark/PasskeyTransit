# Anonymous artifact staging copy

Updated on 2026-10-26 for local preparation only. The archive is not uploaded to an external service and has no reviewer URL.

The builder copies a closed list of source, protocol, table and public report files, the original Phase 14 replay ZIP, and four raw synthetic C1/C2/C3 JSONL datasets from the v0.7.1 release. It removes the project commit field from raw rows, excludes Git history and identifying provenance manifests, fixes ZIP timestamps and platform metadata, and scans the archive and nested replay members for direct identifiers. The archive has its own SHA-256 manifest. Its verifier checks 6,144 C1 rows, 96 route-by-stratum groups, 80 C2 rows, 960 C3 sequences, 1,920 C3 events, and byte equality between the Phase 14 replay and both retained reports. The separate provenance sidecar links replay SHA-256 values to GitHub Actions runs. The public-report verifier recalculated four Phase 14, 16 Fenko and 24 Fenko round-trip, and 12 Proton signatures, with their scoped PRF digest relations. Clean Windows and Linux checkouts produced the same archive SHA-256 `9fa07f23c72eb97261fb27063a06a6389e5c71a0032d9f82ef81671489cc2035`.

The staging copy at that milestone also contained the original Fenko and Proton ZIPs from a successful same-team GitHub Actions run, plus their three reports. A clean extraction checked ZIP-to-report byte equality and recomputed 40 Fenko signatures and 18 PRF bindings, and 12 Proton signatures and 12 PRF relations. The identifying run and artifact digests are in a separate local provenance sidecar, outside the anonymous archive. The original local provider replay ZIP is retained separately. These checks cannot prove provider internals, independent replication, or an exchange between installed provider apps. The public history of this project may allow contextual deanonymization even after direct identifiers are removed. This is not a complete USENIX submission artifact. Independent review is paused by the author.

The current archive also includes the pinned Proton Pass common 2.0.0 direct-HPKE exchange reports and code. From a clean extraction, `verify.py` checks four basic-auth controls, eight passkey controls, seven reverse-direction controls, and the recorded four software assertions. These results concern Proton's direct CXF ciphertext profile; the published CXP draft requires a ZIP with JWE members. No transfer between two provider apps or deployed RP assertion is represented.

To rebuild: run python tools/build_anonymous_artifact.py from the project root. To check an extracted archive: run python verify.py in the extracted directory. See audit.json for the archive hash and row counts.
